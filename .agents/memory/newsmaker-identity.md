---
name: Newsmaker visual identity
description: User-approved branding direction and the boundary between visual changes and MRG behavior.
---

MRG should use Newsmaker's company identity rather than an unrelated visual palette: blue, navy, white, and clear MRG · Newsmaker branding. Keep mobile navigation and expandable details suited to an MRG utility; do not replicate the entire news homepage.

**Why:** The user approved matching the supplied Newsmaker design so MRG feels like a feature of the same product.

**How to apply:** Use official company assets and verify brand styling against the current source. Branding changes must not alter calculations, data sources, manual-position behavior, or the meaning of risk states. Warning colors and text remain distinct from company colors.

The app has two primary uses: clean, elegant live marketing presentations and self-guided education for novices or independent traders. Support PC, mobile, and tablet. Favor clear action buttons, disclosures, and short interactive help rather than long text and stacked forms.

**Why:** The user explicitly described both audiences and requested device-responsive, mobile-first navigation.

**How to apply:** Beginner help should explain risk and Martingale/Averaging at the point of use without filling the screen. Critical warnings must stay clear and visible in both presentation and independent-use flows.

The user approved a chart-first Technical view, with the chart directly visible rather than behind an opening button or dropdown. Keep the page header compact and group app controls instead of leaving an isolated Install row.

**Why:** The user called the scattered empty areas and introductory band awkward, and approved automatically requesting TradingView when entering the Technical tab.

**How to apply:** Preserve this chart-first direction in later UI refinements. Keep technical source distinctions and critical warnings readable; reduce duplicate text and unused spacing rather than hiding risk information.

Remove dropdowns that only contain a short explanatory description, along with the redundant description. Keep the layout consistent across pages, not just Technical.

**Why:** The user said the other pages were also messy and asked to remove dropdowns containing only one line of explanation.

**How to apply:** Prefer useful controls and data over decorative explanations. Preserve meaningful form/filter/data disclosures, novice term help, and essential visible risk/source warnings.

Desktop and mobile must have intentionally adapted layouts and interaction behavior, not merely scaled elements. Check expanded forms as well as the closed dashboard.

**Why:** The user repeated that responsive work was incomplete after an expanded settings form left a large blank desktop column.

**How to apply:** Evaluate useful screen space and the complete interaction state, not only horizontal overflow.

The user chose separate adaptive panels for recording positions, editing limits, and comparing simulations: wide on PC/tablet, nearly full-screen with one-column fields on phones.

**Why:** The user approved this pattern instead of keeping long forms in the page or a narrow sidebar.

**How to apply:** Keep the dashboard compact and risk warnings available inside the active panel. Preserve the directly visible chart and adapt controls to orientation and available keyboard space.
