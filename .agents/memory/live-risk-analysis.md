---
name: Live risk analysis direction
description: Product direction under discussion for adding live pricing and analysis to RiskCheck XUL10.
---

RiskCheck is already presented as a feature in the Newsmaker eBook portal; access is behind Newsmaker login (the user says Google ID). Newsmaker is a fundamentals/technical information portal, not a broker or trading service; the user wants RiskCheck's manual, passive assessment to use real-time market conditions and Newsmaker analytical materials. The user is willing to start with TradingView symbols and adjust them to XUL10 later, but whether this is chart display only or intended as calculation input remains to clarify. Standard TradingView widgets are display tools, not an API that RiskCheck can use to read quotes or indicators; per-symbol data may be delayed. A supplied TradePilot technical note describes a Newsmaker-branded live-quote upstream that maps raw XUL10 to XAU/USD, plus daily/weekly history from that upstream. Its intraday XAU/USD candles instead map to Yahoo `GC=F`, which may not match the XUL10 price basis. The Newsmaker API PDF documents the economic-calendar endpoint `/v1/newsmaker/kalender-ekonomi`; it is Bearer-authenticated and cache-backed, paginates 20 events, and can return 503 when cache is missing. Investing.com offers an embeddable economic-calendar widget under its terms, but that display does not itself supply structured input to RiskCheck.

**Why:** Newsmaker does not provide brokerage or trading execution. The supplied docs suggest sources, but the real-time/history price-basis alignment, feed permissions, event-cache freshness, and intended analysis still need confirmation. The current workspace contains the RiskCheck module, but no visible Newsmaker login implementation.

**How to apply:** Do not treat portal embedding or login as a new feature to build unless the user says the current integration is broken. Keep Newsmaker's role limited to information and analysis, not brokerage or order execution. TradingView symbols can be configurable for chart display, but widgets are not a supported source of calculations; use a separate structured feed for risk logic. Before changing RiskCheck, confirm whether a TV proxy is display-only, that XUL10 live quotes and historical candles share an appropriate price basis, calendar payload fields and cache refresh policy, data rights, fundamental-data scope, and risk limits. Use the PDF's Newsmaker calendar endpoint rather than the TradePilot calendar route when the user requests it. Treat bearer tokens shown in attached documentation as exposed; never copy them into client code or persistent notes. Do not introduce broker integration or automated order placement.
